RUN UNIRETARGET ON ANOTHER GPU SERVER
Current method: wrench_hypergradient / wrench-finite-response (2026-10-16)

Repository: https://github.com/kyounginbaik/SRL_V2D
Agent handoff: AGENT_HANDOFF.txt in this directory
Method/math: ../flash_chord/docs/wrench_hypergradient.txt
Use current main containing finite-response checkpoint selection and frozen-pair
confirmation, together with Adam-response and critic-calibration fixes. Record
the actual checkout commit. Earlier wrench-adam-feedback and wrench-feedback-fast
revisions do not include all of these changes; do not use
their frozen checkout or an existing prepared output root for this recipe.

Always pass --upper wrench_hypergradient. The CLI's default is still the older
Gaussian candidate-search method. These instructions reproduce the NEW method.
Recommended task: FULL episode-1 training, seeds 43/44/45. Use --phase full:
each job automatically validates a full-shape smoke, then starts fresh 100.7M
training if validation passes. No additional approval step is needed between
phases. Other bundled episodes are 3, 5, 6 and 35; run only the requested subset.
Each invocation uses one allocated GPU.

1. HOST AND CLEAN CHECKOUT

Use Linux, NVIDIA Container Toolkit and Docker access. The pinned Dockerfile
requires a compatible NVIDIA driver >=580. Reserve one GPU, 12 CPUs and 96GB
host RAM per job, as in the submitted training recipe. The existing cluster uses
L40S 48GB and B200 GPUs. The smoke now uses the full 2,048-world shape
to validate memory fit and the feedback loop before full training. Inspect
disk space before downloading inputs and building images.
Host Python 3 only needs the standard library; dependencies run in Docker.

  nvidia-smi
  docker version
  git lfs version
  df -h .

On a managed cluster use its allocated GPU; do not share an occupied GPU.
Clone into a fresh directory using your existing GitHub authentication:

  GIT_LFS_SKIP_SMUDGE=1 git clone --branch main https://github.com/kyounginbaik/SRL_V2D.git SRL_V2D_uniretarget
  cd SRL_V2D_uniretarget
  git rev-parse HEAD
  git lfs install --local
  git lfs pull --include='robotic_grounding/uniretarget/**,robotic_grounding/flash_chord/src/flash_chord/assets/**' --exclude=''

SSH cloning is also supported. All following commands run from this repository
root. Selective LFS includes the five references, submitted visual/collision
meshes, URDFs, Sharpa assets and finger PCA prior (roughly 0.42 GiB; Docker and
Git history need additional space). No reconstruction weights, ComPose archive,
source video, final_submission.zip or recursive submodules are needed.
Reference-overlay videos compare robot trajectories, not source RGB footage.

Keep this checkout unchanged while any jobs use it. The portable launcher
bind-mounts source; prepared flash_chord is a symlink, not an immutable snapshot.
Preparation verifies checksums, including package documentation, Python and
YAML configs. Updating code or these docs after preparation can invalidate a
run root on its next launch. Pull updates BEFORE preparing. Use a separate
checkout and fresh root for later changes; do not pull into an active checkout.

2. BUILD THE PINNED CONTAINER

  docker build -f robotic_grounding/flash_chord/docker/Dockerfile \
    -t flash_chord:chord100m-base robotic_grounding/flash_chord
  docker build -f robotic_grounding/uniretarget/Dockerfile.media \
    -t uniretarget:chord100m robotic_grounding/uniretarget

The first image installs the checked-in uv.lock; the second adds video tooling.
Do not replace the locked environment with latest pip packages. Record image IDs:

  docker image inspect uniretarget:chord100m --format '{{.Id}}'

An existing compatible image can be selected with --image or UNIRETARGET_IMAGE.
The original cluster's flash_chord:mixed-ep01-media tag is not required elsewhere.

3. OUTPUT LOCATION AND W&B

Choose a NEW root on persistent storage. This example stays inside the checkout:

  export UNIRETARGET_RUN_ROOT="${UNIRETARGET_RUN_ROOT:-$PWD/.uniretarget/wrench-finite-response-full-run1}"
  export UNIRETARGET_IMAGE="${UNIRETARGET_IMAGE:-uniretarget:chord100m}"

Seeds and episodes may share this root; each has a separate run directory and
lock. Never launch the same episode/seed twice concurrently. A retry after
training has started needs a fresh root. No complete bilevel resume is supported.
An actor checkpoint alone cannot restore the full learner, upper models/replay
and optimizer states. --phase pilot also starts fresh; it is not resume.

For online W&B:

  export WANDB_MODE=online
  export WANDB_ENTITY="${WANDB_ENTITY:-DexDreamer}"
  export WANDB_PROJECT="${WANDB_PROJECT:-v2d-track3-uniretarget}"
  export WANDB_BASE_URL="${WANDB_BASE_URL:-https://api.wandb.ai}"

Provide WANDB_API_KEY securely through this server's environment/secret store.
The portable launcher forwards it, but does not mount the host's .netrc or copy
credentials from the other server. For a private deployment, set its actual API
endpoint instead. A W&B browser/proxy URL is not necessarily an API endpoint.
Leave UNIRETARGET_RUN_TAG unset to get a unique host/output-root hash. If you
set it explicitly, use a fresh tag per server/experiment/root to avoid run-ID
collisions. Episode, seed and phase are added to the run ID automatically.

Without WANDB_MODE=online, portable runs default to offline and will not appear
in the web UI. Metrics and videos are still retained locally. Check
wandb_sync/run.json for the actual run URL, and live_sync.log for upload errors.
Queued Slurm jobs do not appear in W&B until their training phase starts.

5. RECOMMENDED: THREE FULL RUNS ON ALLOCATED GPUS

Choose either this direct-GPU route OR Slurm in section 7. From the repository
root, after setup/preparation above, replace GPU_UUID_OR_INDEX with a device
allocated to this process. This loop runs the three seeds sequentially on that
one GPU; use a persistent session and retain each log:

  export UNIRETARGET_GPU=GPU_UUID_OR_INDEX
  mkdir -p "$UNIRETARGET_RUN_ROOT/launch_logs"
  for seed in 43 44 45; do
    python3 robotic_grounding/uniretarget/launch.py \
      --upper wrench_hypergradient --episode 1 --seed "$seed" --phase full \
      --gpu "$UNIRETARGET_GPU" \
      >"$UNIRETARGET_RUN_ROOT/launch_logs/episode_000001_s${seed}.log" 2>&1 || break
  done

For concurrent runs, use three separate allocated GPUs and invoke the same
command once per seed in separate persistent sessions, changing --gpu to the
matching device. Do not run simultaneous seeds on one occupied GPU. Slurm below
handles separate allocations automatically.

--phase full is the recommended single command: it runs targeted CPU checks,
full-shape GPU smoke, validates its report, and then automatically starts fresh
100.7M training in the same allocation. A failed smoke prevents full training.
The full stage appears under runs/pilot; "pilot" is only an output-path label.
All three episode/seed paths must be untouched in the chosen root. This is
not resume, and full must not be rerun over an existing smoke for the same seed.

Optional smoke-only route, when intentionally checking integration first:

  python3 robotic_grounding/uniretarget/launch.py \
    --upper wrench_hypergradient --episode 1 --seed 43 --phase smoke \
    --gpu "$UNIRETARGET_GPU"

This stops after validation. If it passes, use --phase pilot from section 6
for that seed/root instead of rerunning --phase full.

The smoke runs targeted CPU tests, then 2,048-world training for 524,288 MAIN
environment transitions. It uses the same batch 1,024 and replay settings as
full training, performs one upper round at 501,760, and saves final videos.
Matched complete FlashSAC adaptation uses three checkpoints per branch. The
first checkpoint is the later of 64 vector steps or the scoring interval end
plus 16 steps; the next checkpoints add 32 steps each. A strict cap of 448
vector steps applies, including all checkpoints. Episode 1 fits within the cap.

For an early scoring interval this can be 64 / 96 / 128 vector steps, or
131,072 / 196,608 / 262,144 transitions per branch. Later windows receive more
time but never exceed 917,504 transitions per branch at 2,048 worlds. Actual
coverage and lower actor/critic learning are checked, not assumed from a budget.
One unchanged control curve is reused across up to four candidate windows.
All selected proposals are still tested at all three checkpoints. Main training
pauses for this work. Keep the best physically eligible checkpoint per window;
a later worse checkpoint does not erase it. Eligibility requires actual lower
learning/coverage, all object and archived-prefix guards, and gain over BOTH
the incoming pair and same-budget unchanged control greater than
max(.001, .005*abs(min(incoming_cost, control_cost))).

Confirm at most two eligible pairs, ordered by measured cost. Freeze candidate,
matched control and incoming policies and repeat each full-horizon VOC=0 rollout
from the same fixed initial state. No more training or changed initial joints.
The worse candidate score must beat the better original/repeat score of each
comparison by the same margin; all guards remain active. At most six additional
single-world rollouts are required per upper round. Only the published proposal
is marked accepted. Plateau stability remains diagnostic, not a publication veto.

Before any proposal, calibrate the upper critic for 32 updates on the fresh
unassisted baseline's complete discounted returns. Proposal validation samples
only this upper round's baseline generation, not old controller rollouts under
the same reference version. After every candidate/control checkpoint, its
unassisted evaluation also supplies actual return targets, even for rejected
candidates. Each dataset remains tied to its exact reference and lower actor;
it never enters current-reference actor replay. Trial datasets are discarded
after fitting; only upper model/optimizer state persists.

Complete-rollout calibration defaults to MC weight 1. If another weight is
configured, apply Huber to the blended TD/MC TARGET, rather than averaging two
Huber losses whose gradients can cancel. TD immediate costs, MC returns and
upper edit regularization all use cost_scale=.01. Prediction/error records
include explicit normalized and raw aliases; neither unit is a physical force.
The upper objective remains measured full-horizon support cost. Early tracking
resets leave terminal observations at a stale reference frame because the
lifecycle did not advance. Mark those rows critic_valid=false and exclude them
from upper TD fitting, while retaining them for inner actor replay. Full-horizon
baseline/trial MC provides actual continued-failure evidence. Upper done marks
only reference-horizon completion; lower FlashSAC termination is unchanged.

Require process exit code zero AND this report to contain passed=true:

  $UNIRETARGET_RUN_ROOT/reports/smoke_validation_episode_000001_s43.json

  python3 -m json.tool "$UNIRETARGET_RUN_ROOT/reports/smoke_validation_episode_000001_s43.json"

The validator requires actual learned proposals, nonzero lower actor/critic
learning, finite saved state, identical initial-state audits and saved media.
It also requires measured feedback for every candidate/control checkpoint,
nonzero upper-critic parameter updates, fresh-baseline calibration/generation
audits, and adaptation within the configured cap.
A completed training stage alone is insufficient: the validator runs afterward.
Zero accepted edits can pass integration; report that outcome honestly and do
not infer task improvement merely from a nonzero upper gradient.
--phase smoke stops here; it does not automatically start full training.

6. START FULL TRAINING AFTER VALIDATION

After the same episode/seed/root's smoke report passes:

  python3 robotic_grounding/uniretarget/launch.py \
    --upper wrench_hypergradient --episode 1 --seed 43 --phase pilot \
    --gpu GPU_UUID_OR_INDEX

pilot skips smoke and does not itself verify the earlier report; inspect the
report first. It starts FRESH 2,048-world training for 100,663,296 main steps,
not a continuation of smoke weights. Upper updates occur every 501,760 steps;
checkpoint/media interval is 1,003,520 plus final save. The name "pilot" is an
output-path compatibility label, not a short training budget.

For a fresh episode/seed/root with no earlier smoke, use --phase full to run
smoke followed automatically by fresh full training in the same allocation.
A failed smoke prevents full training. Do not use full after already running
smoke for that same episode/seed/root; rerunning smoke rejects existing outputs.

Full training uses the SAME bounded adaptation settings as the smoke. These
extra transitions are separate from the 100.7M main budget. At most one control
plus four candidates are trained per upper round. Later failure windows take
more work than early windows. All three scheduled checkpoints are tested;
selecting a finite lower response does not require an adjacent-checkpoint
plateau. Empirical stability remains logged with success resolution max(.02,1/N).
Physical regression/improvement guards and frozen-pair confirmation still apply.
A bounded budget may miss benefits requiring more lower training. No lower-
convergence claim is made and the lower-training cap is unchanged.
There are no 2,048 upper candidates: there is one learned proposal per window.

7. RECOMMENDED SLURM ROUTE: THREE FULL JOBS

Submit from the repository root with the output/image/W&B environment above.
Replace YOUR_PARTITION and adjust the walltime/account/QoS to this cluster.
These commands submit three independent jobs, each automatically running its
smoke and then full training. The portable script uses the allocated GPU;
no original node names or device indices are required.

GPU allocation resolution defaults to UNIRETARGET_GPU_ID_KIND=auto. UUID
allocations are unambiguous; numeric allocations may be Linux device minors or
nvidia-smi indices. Auto stops if those mappings disagree. Confirm this site's
Slurm convention, then set UNIRETARGET_GPU_ID_KIND=minor or index as appropriate.
The original node01/node100/node200 cluster uses minor. Do not assume another
server uses the same convention. A single allocation can explicitly provide
UNIRETARGET_GPU_UUID; do not reuse one fixed UUID across the three Slurm jobs.

  export UNIRETARGET_PARTITION=YOUR_PARTITION
  export UNIRETARGET_SLURM_TIME="${UNIRETARGET_SLURM_TIME:-7-00:00:00}"
  mkdir -p "$UNIRETARGET_RUN_ROOT/slurm_logs"
  for seed in 43 44 45; do
    sbatch --export=ALL --partition="$UNIRETARGET_PARTITION" \
      --time="$UNIRETARGET_SLURM_TIME" --job-name="whg-e1-full-s${seed}" \
      --output="$UNIRETARGET_RUN_ROOT/slurm_logs/%j.out" \
      --error="$UNIRETARGET_RUN_ROOT/slurm_logs/%j.err" \
      robotic_grounding/uniretarget/train.sbatch 1 "$seed" wrench_hypergradient full
  done

Arguments: EPISODE SEED UPPER PHASE. The explicit fourth argument full ensures
smoke-to-full execution. One GPU, 12 CPUs and 96GB RAM are requested per job.
The seven-day walltime above is a scheduler limit, not a runtime prediction;
choose a limit supported by this cluster. --export=ALL forwards the configured
root/image/W&B environment. Do not also run direct-GPU commands for these paths.

Optional staged alternative: change full to smoke to run integration only.
After each report passes, submit the corresponding seed with pilot to start
fresh full training without repeating smoke. For existing passed smoke paths,
use pilot; for untouched paths, use full. A pilot invocation does not itself
check the earlier report, so inspect it first. Do not submit duplicate jobs.

METHOD CONTRACT / VALIDATION LIMITS

The upper outputs a local 56D correction (12 wrist + 44 finger dimensions),
using a normalized wrench-support cost critic and a gradient through three
temporary lower actor Adam updates. They start with the incoming actor's actual
moments/count and schedule, retaining production learning-rate multipliers and
parameter projection. sqrt(v_hat + 1e-12) regularizes the derivative at zero
second moments; this is an explicitly approximate Adam response. Lower critics,
temperature, statistics and sampled experience stay frozen inside this graph.
This is not three simulator timesteps or three complete SAC updates. Full FlashSAC
adaptation on fresh experience compares the edited and unchanged references
from the same incoming learner. Accepted pairs publish all tested learning
state; rejected edits preserve the incoming pair/replay. Long adaptation is
outside the gradient graph. Selection is among finite adapted policy/reference
pairs; frozen confirmation is an empirical check, not proven convergence.
The cost describes object-centric wrench support, not measured net force/torque.

Keep the bundled objects/references, fixed frame-zero physical starts, pot
0.2kg and lid/spoon 0.1kg, wrist kp=100/kd=12/effort=90, no added wrist speed cap,
hand-keypoint reward weight=2 and finger-joint tracking weight=0.25. VOC starts
at 1 and decreases by performance gates. Upper evaluations remain VOC=0.
Object trajectories/contact targets are immutable during refinement.

Run the focused CPU checks and full-shape GPU smoke on the destination server.
The smoke validates the measured feedback connection and bounded adaptation;
it does not prove critic accuracy, convergence, or successful reference edits.
Record the measured round duration rather than extrapolating from main steps.
The preceding plateau-gated recipe measured about 5.4-5.5 minutes per upper round
but rejected 402/405 proposals on stability. Of 56 proposals with a useful
checkpoint, 32 were useful only at an earlier checkpoint. These observations
motivate the change; they do not establish that new frozen confirmations will
pass. Measure accepted edits and actual reference motion in the new run. Do not
attribute older frozen runs' outcomes to the current finite-response changes.

Legacy --upper gaussian / --upper flashsac remain available for the earlier
candidate-search/convex-head-response ablation. They use different algorithms
and budgets. Historical instructions are in RUNNING.txt at commit 721cf423;
their formulation is ../flash_chord/docs/response_bilevel.txt. Do not omit the
new --upper flag or apply the old convex residual guarantee to this engine.
