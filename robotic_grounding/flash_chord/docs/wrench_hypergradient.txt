WRENCH HYPERGRADIENT ENGINE: FINITE RESPONSE AND FROZEN-PAIR CONFIRMATION
Updated 2026-10-16

This is the current wrench-finite-response implementation. It is separate from
response_bilevel and supersedes the plateau-gated wrench-adam-feedback recipe,
the 2026-10-15 validation recipe and the first wrench-feedback-fast revision.
Older frozen runs do not acquire these changes. Use current main, record its exact commit, and prepare a new source
snapshot/output root. New GPU performance has not yet been measured.

ACTUAL ALGORITHM

1. Ordinary lower FlashSAC trains with the configured tracking, physics and
   regularization rewards. Capture 32 worlds every four vector steps into a
   32,768-row auxiliary buffer: frame, observation, action, critic context,
   next observation, done, critic_valid, measured wrench-support cost and
   upper-round generation.
   This main/baseline
   buffer belongs to one accepted-reference version; mixing versions is rejected.
2. Every 501,760 main environment transitions, evaluate the current pair from
   the fixed start without VOC. Add these transitions to that auxiliary buffer.
   Detect object failure and select up to four earlier windows using the
   onset/threshold/history selector. The upper actor does not learn the window
   index. Every selected window is still eligible for a physical trial; this
   recipe does not use a critic-ranked shortlist to skip selected proposals.
3. Fit twin discounted wrench-cost critics from main/baseline replay. Current
   lower deterministic actions supply TD targets; max(twin cost) is pessimistic.
   Early tracking resets have terminal observations at a stale reference frame
   because that lifecycle did not advance. Mark these rows critic_valid=false
   and exclude them from upper TD fitting. Keep their current observations in
   the inner actor replay. The upper done flag represents only the reference
   horizon; ordinary lower FlashSAC termination remains unchanged.
   Hold out rows from the current fitting round and report their TD error.
   Then calibrate for 32 updates on the complete measured return of THIS round's
   unassisted baseline, using its exact incoming controller. Only after this
   calibration generate proposals. The outer evaluation batch filters both
   source=baseline and the current generation; old controllers' baseline states
   under the same reference version cannot enter it. Measured trial feedback
   below adds further calibration, including for rejected edits.
4. For each window, compute feasible coefficient intervals using joint,
   cumulative-offset and correction-speed bounds. Build a local reference
   Jacobian with finite differences (normalized radius at most 0.01) through
   the edit and Newton FK, with one-sided derivatives at active limits.
   Recompute reference-conditioned observations in JAX and check zero-edit
   reconstruction. Measured state, old actions, object targets and desired
   support remain fixed. Simulator trajectories and sampled-state distributions
   are not differentiated; this is a local reference linearization.
5. The upper MLP produces one bounded 56D correction: 12 wrist and 44 finger
   dimensions. Starting from the incoming lower actor, take three differentiable
   projected Adam steps on the SAC actor loss using relabeled replay. Start from
   that actor's actual Adam moments/count and learning-rate schedule clock.
   Use the configured Adam betas, epsilon, learning-rate multipliers, residual
   mean scaling and parameter projection. For differentiability at zero second
   moments, use sqrt(v_hat + 1e-12) + epsilon instead of sqrt(v_hat) + epsilon.
   This is an explicitly regularized approximation to production Adam.
   All actor parameters are editable; lower critics, temperature, batch
   statistics and sampled noise remain fixed. These are learning updates, not
   simulator steps or complete FlashSAC updates. The old fixed-rate SGD and
   ridge-head responses do not describe this version.
6. Score the adapted actor using the learned upper cost critic. Differentiate
   through the three actor updates and reference observations into the upper
   actor. Four upper Adam steps produce the proposal, with normalized radius
   0.25: at most 5 mm per wrist translation axis and 0.05 rad per finger/rotation
   coefficient before additional cumulative/rate constraints. Smoothly map the
   actor output into its feasible box. A neutral actor uses the box midpoint;
   a joint at its limit may therefore receive a small inward correction.
   The separate zero-edit control remains exactly zero.
7. Physically validate against a matched unchanged-reference control. Both
   branches start from the SAME complete incoming FlashSAC learner, including
   optimizers, target critic, temperature, normalization and scheduler clocks.
   Neither starts from the three-update actor copy. Each gets isolated fresh
   replay and actual simulation, with complete ordinary FlashSAC learning.
8. Use three BOUNDED checkpoints derived from the common scoring interval.
   Let S be its exclusive final frame, W the training-world count, and M the
   adaptation replay warmup in vector steps. The first checkpoint is:

     first = min(max(64, S + 16, M + 16), 448 - 2*32)
     checkpoints = W * [first, first + 32, first + 64]

   The hard cap is 448 vector steps per branch: at W=2048, at most 917,504
   transitions. Early intervals can use 64/96/128 vector steps, or
   131,072/196,608/262,144 transitions. Later windows get enough nominal time
   to reach their interval where the cap permits. Episode 1 has 335 reference
   frames and fits within this cap. Other longer episodes may hit the cap
   before late windows; actual coverage remains mandatory and is reported.
   No nominal budget proves that early termination allowed the worlds to
   reach the interval. The former 1/2/4-full-horizon schedule is replaced.
9. Hold incoming reward weights and VOC stage fixed during adaptation. Match
   learning/reset seeds and original reset joints across branches. Replay has
   262,144 transitions; learning begins at max(8,192, batch size). Even during
   replay warmup, collect with the warm-started policy. At every checkpoint,
   evaluate the frozen branch actor over the full horizon, deterministically,
   from the fixed start with VOC=0. These evaluations also teach the upper critic.
10. Record each evaluation in an isolated TrialRollout, identified by its exact
    reference and actor-policy digest. Capture transitions before mutation or
    donation. Require physically consecutive frames within each segment.
    Evaluation disables early tracking resets and continues through the full
    reference horizon, observing actual failed-object motion. Keep completed
    horizon segments; discard incomplete collections rather than treating them
    as full returns. Compute each completed segment's discounted observed G_t.
11. Fit the upper critic for 32 updates on that branch's recorded observations
    and actions. Complete rollouts default to measured-return calibration:

      scale = .01; default MC weight w = 1
      TD target = scale*observed cost + .99*(1-done)*max(target twin cost
                    at next observation and THIS branch's lower action)
      blended target = (1-w)*TD target + w*scale*G_t
      loss = Huber(prediction, blended target)

    Ordinary replay TD labels use the same scale. If a different MC weight is
    configured, blend TARGETS before applying Huber: averaging separate clipped
    losses could cancel their opposite gradients despite a large measured error.
    The default w=1 uses the observed return directly. Both twin critics are
    trained and their targets updated. Check that the
    provided bootstrap learner matches the recorded actor-policy digest.
    Hold out rows from parameter updates; log before/after return prediction
    error, measured return, update count and critic parameter change. This is
    observed outcome supervision, not merely another self-consistent prediction.
    A held-out row error is still not a guarantee of gradient accuracy or
    independent-trajectory generalization.
12. Apply this feedback BEFORE deciding acceptance, for every tested control
    and candidate checkpoint. Rejected edits therefore teach the critic too.
    Trial data retain their recorded branch context: they are not relabeled
    as accepted-reference samples and never enter the main lower replay or
    current-reference actor-proposal replay. The shared critic weights retain
    these updates. Trial datasets are discarded after their fit; there is no
    persistent cross-policy trial replay. Each new round recalibrates against
    its fresh baseline. Updates can inform later proposals, but their accuracy
    is not guaranteed and policy changes still make this an approximate value model.
13. Train the unchanged control curve once and reuse it at matching budgets
    for all candidate windows. Candidate training continues between checkpoints
    with its own physics, replay and optimizer state. At most one extra vector
    training scene is alive at once. Main training pauses during validation;
    additional transitions are reported separately from main steps.
14. Train and evaluate ALL THREE predeclared checkpoints. Plateau/stability
    diagnostics are still logged, but cannot veto finite_response acceptance.
    Both branches need at least 32 actor/critic updates and nonzero parameter
    movement. The candidate also needs 128 observed failure-region samples
    and coverage of the interval's final frame. A control that still fails
    earlier remains a valid negative comparison; its coverage is recorded.
    At each checkpoint require improvement over BOTH the incoming pair and
    the unchanged control at the SAME training budget, plus existing per-object
    and archived-prefix guards. With B=min(control_cost,incoming_cost), require
    B-candidate_cost > max(.001, .005*abs(B)). Keep the best eligible checkpoint
    per window, with its exact complete lower learning state. A later worse
    checkpoint must not overwrite an earlier useful one. The legacy plateau
    mode remains explicit; it is not the current portable recipe.
15. Rank eligible pairs by measured local cost and attempt at most two frozen
    confirmations, stopping at the first pass. For each, freeze its candidate,
    same-budget unchanged control and incoming learner; run one full-horizon
    VOC=0 evaluation of EACH from the SAME audited initial physical state.
    There are no additional learning updates or randomized initial joints.
    Use the worse original/repeat candidate score and the better original/
    repeat control and incoming scores, retaining the same improvement margin
    and object/prefix guards. A one-off favorable rollout cannot alone justify
    publication. At most six extra single-world rollouts are added per round;
    vector-world training budgets remain unchanged.
16. Publish only the passing reference and ALL its exact tested lower learning
    state, retaining Adam moments. Reset episode return accumulation at frame
    zero and clear main/auxiliary replay. Mark only the published proposal
    accepted. Rejection retains the incoming learner/reference/replay; upper
    critic learning from measured trials persists regardless of this decision.

WHAT THE WRENCH LABEL MEANS

The cost is an object-centric contact wrench SUPPORT descriptor, not measured
six-axis net force/torque. It uses squared relative tolerance-band error
(weight 5), missed support and unintended support energy. All hands participate,
objects receive equal weight, and targets remain immutable. The upper objective
is measured full-horizon support cost. Full-horizon baseline/trial evaluations
supply actual continued-failure evidence after a missed grasp or bad contact.
Early training resets have stale-frame terminal observations and are excluded
from upper TD fitting with critic_valid=false; they remain available to the
inner actor replay. Upper done marks reference-horizon completion only. This
filter does not change the lower FlashSAC termination/reset behavior.
VOC/reset context is included in the critic input. Stored labels are raw
dimensionless support costs; critic targets and predictions use scale=.01.
Both normalized and raw diagnostic aliases are logged. These are not meters,
Newtons or official Track 3 scores. The physical acceptance score is unchanged.

MATHEMATICAL SCOPE (PLAIN TEXT)

theta = 56 local reference coefficients; phi = full lower actor parameters.
z_0 = incoming lower actor parameters, Adam moments/count and schedule clock.
z_{k+1}(theta) = projected, differentiable Adam actor update on SAC_loss,
                 with the configured schedule and eps_root=1e-12.
phi_K(theta) = actor parameters extracted from z_K(theta).
F_K(theta) = mean(Q_wrench(obs(theta), pi_phi_K(theta)(obs(theta))))
             + .01 * regularization * mean(theta^2).

Physical selection uses a separate finite-response problem. Let L_B(theta)
be complete FlashSAC adaptation for a predeclared budget B from the incoming
learner. Select among the three finite pairs (theta, L_B(theta)), subject to
measured improvement, physical guards and frozen-pair confirmation. This does
not require L_B to converge. The K=3 actor gradient proposes theta; it is not
claimed to be the exact gradient through this longer physical response.

Q_wrench predicts the .01-scaled return. Scaling the edit regularizer by the
same amount preserves the intended return-versus-edit tradeoff. Use *_raw
metric aliases to recover unscaled dimensionless return units.

Autodiff computes the gradient of this finite K=3 response and learned
surrogate, including the reference-observation path. Log total gradient,
direct gradient with phi_K detached, and their difference, which isolates
the contribution through lower learning. Reference finite differences and
fixed replay/state distributions and regularized Adam are additional approximations.

This is finite-step bilevel optimization with an approximate learned objective.
It is not an inverse-Hessian implicit-gradient method, stock upper FlashSAC,
or a certified derivative of discontinuous contacts or converged neural RL.
Physical lower adaptation and measured trial critic fitting are outside this
proposal's autodiff graph. Their gradients are not claimed equal to the short
response gradient. Trial supervision closes the observed-outcome feedback loop;
it does not establish convergence, accurate action gradients or task success.

and explicitly select --upper wrench_hypergradient. Keep the existing episode,
meshes, masses, controller, rewards, fixed starts and lower-training settings.
Use a fresh source snapshot/output root: full training resume is not implemented.

Require the smoke validation report to pass: actual lower learning, finite

that is historical timing, not a measurement of the new confirmation path.

OBSERVABILITY

W&B run names begin wrench-finite-response-full-d56-w2048-.
Existing gradient, predicted gain, measured gain, acceptance, committed wrist
and finger changes, physics videos and historical reference overlays remain.
upper_feedback/* reports measured rows, critic updates, parameter movement,
held-out return errors and fitting time, with explicit normalized/raw units.
Each round records baseline_critic and baseline_metrics, as well as candidate
control_guard_reasons and baseline_guard_reasons to separate their vetoes.
Adaptation and main transition clocks
remain separate; total work includes all trials and evaluations.

upper_updates.jsonl / search_batches/step_*/scores.json record each window,
56D proposal, prediction, actual physical score, budget and rejection reason.
critic_feedback.jsonl records each branch/checkpoint's measured-feedback fit
as it finishes, including rejected candidates. adaptation_progress.jsonl gives
actual lower updates, frame coverage and metrics. upper_state.msgpack preserves
the learned upper state; selected_reference.npz and the demo archive record
published policy/reference pairs. Predicted discounted support return and
physical local score (pose/support/stability/edit penalty) have different scales.

TEST COVERAGE AND LIMITATIONS

Focused tests cover independent finite-difference/analytic hypergradients,
production FlashSAC Adam-response comparisons, incoming optimizer-state reuse,
regularized zero-moment derivatives, feasible reference relabeling, terminal handling,
copy/donation safety, matched branch identity, complete-segment MC returns,
rejected-candidate feedback, non-cancelling calibration, consistent return
scaling, current-generation baseline sampling, invalid reset-transition filtering,
one-frame success stability diagnostics, held-out rows, bounded budgets, fixed
starts, earlier-checkpoint retention, frozen-pair confirmation and publication.
Launcher tests reject a disconnected feedback loop or exceeded cap. CPU checks do not establish GPU task improvement.
The fresh full-shape smoke and subsequent runs provide integration and measured
performance evidence. The prior plateau-gated experiment had 402/405 proposals
rejected for instability; 56 had a useful checkpoint and 32 were useful only
at an earlier checkpoint. The same nominal pair also sometimes changed its
failure time across repeated deterministic evaluations despite identical
initial state. Frozen confirmation addresses single-rollout selection bias;
it is not a proof of simulator determinism or robust task success. New accepted
reference changes must still be measured. Old 2026-10-15 runs did not use the
current trial feedback loop.

Conceptual background: finite inner-optimization differentiation,
https://proceedings.mlr.press/v80/franceschi18a.html . Its convergence conditions
are not asserted for this learned-critic/contact-simulation implementation.
